Attention Anyway?

A fixed-size state carries corrections forward without attending over history.

Dario Fumarola · Amazon Web Services

Keeping a correction in memory saves work at later decisions. In paired tests, the optimizer needs 23.1% fewer derivative evaluations in navigation and 23.9% fewer in chain control over the next eight decisions, with the network weights fixed.

Idea

{% include memory-demo.html %}

Navigation: an agent crosses a maze with narrow doorways and moving circular obstacles to reach a goal.

Chain control: a 12-link articulated chain reaches three targets while avoiding obstacles, self-collision and joint limits.

Each decision receives a new observation, updates the hidden state and executes the first action of a short plan.

Evidence

When the optimizer resumes after a shared correction, retaining the state reduces the work it repeats over the next eight decisions. We count residual-Jacobian evaluations: computing the task errors and their derivatives for an optimization update.

Navigation uses 9.3 evaluations after retention versus 12.1 after discard; chain control uses 10.8 versus 14.2. Paired 95% intervals for the reductions are [17.0, 29.0]% and [17.5, 30.0]%.

To measure the memory effect alone, we also disable further optimization and replay identical observations into both branches. Retaining the state lowers the next proposed plan's task loss by 3.2% in navigation and 4.4% in chain control.

After four decisions, those reductions fall to 1.1% and 1.7%. By the eighth decision, both estimates are close to zero.

Beyond a cached plan

Reusing a corrected action sequence already saves work. We gave both branches the same corrected plan in their cache and resumed the same action-space solver. Keeping the state as well lowers physical cost over the next eight decisions by a further 0.7% in navigation [0.2, 1.2] and 1.1% in chain control [0.3, 1.9], with paired 95% intervals.

Physical cost measures the movement that actually occurs, with contact and terminal-distance penalties. The state is corrected once in this experiment; the plan cache is refreshed after every solve.

Full episodes and time budgets

Across full episodes, keeping state corrections raises navigation success from 82.7% to 85.4% and chain control from 74.2% to 78.6%, using the same solver and settings as discarding them.

The correction can come from an action-space solver too. Fitting its solution back into memory reaches 85.2% navigation success, close to direct state correction's 85.4%. The shared result is useful carryover in memory, through either route.

At about 3 ms mean controller time, retained state reaches 81.8% navigation success versus 80.8% for warm-started model predictive control (MPC), which reuses its previous plan to initialize the next optimization. At about 8 ms, MPC reaches 89.0% versus retention's 87.0%.

Within the 4 ms envelope, MPC and retention have similar success, 85.8% versus 85.4%, but MPC has fewer contacts: 6.0 versus 14.2 per 1,000 decisions. A contact is a decision with a physical collision against a wall or obstacle. Our objective penalizes small clearance; MPC and the filters also impose predicted-clearance constraints.

The filters prioritize avoiding contact. The control barrier function (CBF) filter adjusts the next action using a local clearance condition; the predictive filter checks a sequence of actions ahead.

Method

The controller proposes a state, then decodes a short action sequence. A local optimizer searches for a nearby state whose decoded plan improves the task objective. Its candidate trials use the same dynamics, residuals and physical limits as direct action refinement.

\(R_t(z)\) combines task errors with a penalty for moving away from the original plan. Its Jacobian \(J\) contains their derivatives with respect to state. A damped Gauss-Newton update gives the search direction:

\[ \begin{aligned} P&=J^\top J+\lambda I,\\ v&=-P^{-1}J^\top R_t(z),\\ z'&=z+\alpha v. \end{aligned} \]

Damping \(\lambda\) stabilizes the direction. The step size \(\alpha\) controls how far the candidate moves. An evaluated loss decrease and cumulative state and action bounds decide whether it is accepted.

  1. Decode the current state and evaluate its objective.
  2. Try a correction within the state-displacement limit.
  3. Keep it if the decoded plan passes the action bound and decrease test. Otherwise halve the step and retry.

The reference configuration allows three candidate trials per decision. Rejected candidates consume a trial and reuse the current direction. After acceptance, a remaining trial may compute a fresh direction.

The recurrence, bounds and decrease test

The recurrence proposes \(z_t^0\), and the decoder maps it to a control sequence. The state-search objective includes both task residuals and a proximity term around the initial plan:

\[ \begin{aligned} z_t^0&=f_\theta(z_{t-1},x_t),\\ U_t^0&=g_\phi(z_t^0;c_t),\\ L_t(z)&=F_t\bigl(g_\phi(z;c_t)\bigr). \end{aligned} \]

The proximity term is part of \(F_t\):

\[ \begin{aligned} F_t(U)&=C_t(U)\\ &\quad+\frac{\mu}{2m}\|S(U-U_t^0)\|_2^2. \end{aligned} \]

\(C_t\) is the task loss, \(\mu\) sets the proximity weight, \(m\) counts scalar controls, and \(S\) scales them by their physical limits.

Every candidate is checked against the same cumulative bounds around the original proposal:

\[ \begin{aligned} \|z-z_t^0\|_2&\leq\rho_z,\\ \frac{\|S(U-U_t^0)\|_2}{\sqrt m}&\leq\rho_U. \end{aligned} \]

With \(b=J^\top R_t(z)\), the Armijo acceptance test is:

\[ L_t(z)-L_t(z')\geq-\eta\alpha b^\top v>\epsilon_t. \]

Non-finite candidates stop the solve. Accepted updates decrease the supplied local objective and remain inside the state ball.

Solving through the output space

The controller has a 256-dimensional state, but its decoded action sequence has 24 dimensions in navigation and 96 in chain control. The exact current-metric solve uses this smaller output space.

Let \(D\) be the decoder Jacobian, \(Q\) the residual Jacobian in action coordinates, and \(A=(Q^\top Q)^{1/2}D\). Then \(P=\lambda I+A^\top A\). The inverse-vector product can be computed as:

\[ \begin{aligned} (\lambda I+AA^\top)q&=Ab,\\ P^{-1}b&=\lambda^{-1}(b-A^\top q). \end{aligned} \]

The inner system is solved by Cholesky factorization. Derivative and factorization work are included in the reported timing.

Rollback

A correction can outlive the conditions that made it useful. Changing the target or delaying sensor records removes the average benefit of retention in these tasks. Keeping the original state for one more decision lets the controller withdraw its latest correction.

The simulator supplies a target identifier and sensor-record age. When this metadata shows a changed target or a record more than one decision old, the controller rolls back before its next recurrent update.

Rollback adds at most 0.02 ms to mean controller time and stays within the same latency limits.

The rollback rule
\[ \begin{aligned} \widehat z_t&=z_t^0+a_{t+1}(\widetilde z_t-z_t^0),\\ a_{t+1}&\in\{0,1\}. \end{aligned} \]

A zero switch restores the original state; a switch of one keeps the correction. Older changes have already propagated through memory. The action that was executed stays the same.

Limits

The study covers one gated recurrent architecture and two simulators with differentiable geometry. It measures what retaining a correction adds within that controller; there is no attention-based baseline.

With stale sensing, the optimizer can improve its supplied objective while physical control deteriorates. Under continuous two-decision observation delay, navigation success falls to 70.4% with retention and 70.9% with discard. A successful local solve can still be working from the wrong geometry.

Contact avoidance is a separate limitation: MPC and the filters have much lower contact rates. Rollback also relies on explicit context metadata and only withdraws the latest correction, leaving older changes in recurrent memory.

Outlook

The next comparison is architectural: does a correction leave a similar trace in a state-space model, or in a transformer's key-value cache? Repeating the same paired experiment would measure how long the benefit survives, how much optimizer work it saves, and what can be withdrawn when the context changes.
