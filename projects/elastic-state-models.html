What the next decision inherits

When a planner repairs an action, the controller can still carry forward the memory that produced the original mistake. The next observation may bring back a similar proposal. Here we test what happens if it carries the corrected memory instead.

Memory is the hidden state carried between observations. After a shared correction and first action, the branches store different states. Both receive the action they actually executed.

What remains after a correction

With further correction disabled, retaining the state lowers the next proposal's task loss by 3.2% in navigation and 4.4% in chain control. Both branches receive the same recorded observations, so the comparison isolates what their memories carry forward.

Most of the benefit is local: it fades over four inputs and is close to zero by eight.

When the optimizer is switched back on, it has less work to repeat. Over the next eight inputs, residual-Jacobian evaluations fall by 23.1% in navigation and 23.9% in chain control.

Full episodes and time budgets

Across full episodes, retaining rather than discarding state corrections raises navigation success from 82.7% to 85.4%. Chain control rises from 74.2% to 78.6%. Retain and discard use the same solver and settings.

Direct action refinement improves the present objective more than state search. Fitting its solution back into memory recovers most of the retention benefit.

Warm-started MPC reaches similar navigation success with substantially fewer contacts: 6.0 versus 14.2 per thousand steps. It also gains more from additional solve time. Retention is most useful here when each solve must stay small.

A small solve inside a fixed controller

The controller proposes a state, then decodes a short action sequence. A local optimizer searches for a nearby state whose decoded plan improves the task objective. Its candidate trials use the same dynamics, residuals and physical limits as direct action refinement.

\(R_t(z)\) measures task errors after decoding a candidate state. Its Jacobian \(J\) supplies a damped Gauss-Newton direction:

\[ \begin{aligned} P&=J^\top J+\lambda I,\\ v&=-P^{-1}J^\top R_t(z),\\ z'&=z+\alpha v. \end{aligned} \]

Damping \(\lambda\) stabilizes the direction. The step size \(\alpha\) controls how far the candidate moves. An evaluated loss decrease and cumulative state and action bounds decide whether it is accepted.

  1. Decode the current state and evaluate its objective.
  2. Try a correction within the state-displacement limit.
  3. Keep it if the decoded plan passes the action bound and decrease test. Otherwise halve the step and retry.

The reference configuration allows three candidate trials per input. Rejected candidates consume a trial and reuse the current direction. After acceptance, a remaining trial may compute a fresh direction.

The recurrence, bounds and decrease test

The recurrence proposes \(z_t^0\), and the decoder maps it to a control sequence. The state-search objective includes both task residuals and a proximity term around the initial plan:

\[ \begin{aligned} z_t^0&=f_\theta(z_{t-1},x_t),\\ U_t^0&=g_\phi(z_t^0;c_t),\\ L_t(z)&=F_t\bigl(g_\phi(z;c_t)\bigr). \end{aligned} \]

Every candidate is checked against the same cumulative bounds around the original proposal:

\[ \begin{aligned} \|z-z_t^0\|_2&\leq\rho_z,\\ \frac{\|S(U-U_t^0)\|_2}{\sqrt m}&\leq\rho_U. \end{aligned} \]

With \(b=J^\top R_t(z)\), the Armijo acceptance test is:

\[ L_t(z)-L_t(z')\geq-\eta\alpha b^\top v>\epsilon_t. \]

Non-finite candidates stop the call. Accepted updates decrease the supplied local objective and remain inside the state ball. Those properties concern the current model and observations.

Solving through the output space

The controller has a 256-dimensional state, but its decoded action sequence has 24 dimensions in navigation and 96 in chain control. The exact current-metric solve uses this smaller output space.

Let \(D\) be the decoder Jacobian, \(Q\) the residual Jacobian in action coordinates, and \(A=(Q^\top Q)^{1/2}D\). Then \(P=\lambda I+A^\top A\). The inverse-vector product can be computed as:

\[ \begin{aligned} (\lambda I+AA^\top)q&=Ab,\\ P^{-1}b&=\lambda^{-1}(b-A^\top q). \end{aligned} \]

The inner system is solved by Cholesky factorization. Derivative and factorization work are included in the reported timing.

When to let a correction go

A correction can outlive the conditions that made it useful. Changing the target or delaying sensor records removes the average benefit of retention in these tasks.

Context rollback keeps the original proposal for one extra input. Before the next recurrent update, it checks the target identifier and record age. If the target changed or the relevant record is more than one input old, it undoes the latest correction:

\[ \widehat z_t=z_t^0+a_{t+1}(\widetilde z_t-z_t^0),\qquad a_{t+1}\in\{0,1\}. \]

A zero switch undoes the latest correction while preserving older changes that have propagated through memory. Rollback leaves the executed action untouched.

Rollback results and evaluation limits

During intermittent sensing delays, rollback raises navigation success from 82.1% to 83.4% and chain success from 71.8% to 73.0% over unconditional retention. Mean time increases by 0.02 ms or less, and both timing limits remain satisfied.

The experiments use one gated recurrent architecture in two simulators with differentiable geometry. Under stale sensing, the supplied objective can improve while physical control deteriorates. Memory timescales and the value of rollback may change with the architecture or with training that includes state corrections.

Looking ahead

A useful correction can improve more than the action that immediately follows it. In these experiments, that extra value lasts only a few inputs.

Longer-running agents will need ways to retain local improvements and discard them when they no longer fit. Testing that balance across architectures, training methods and changing tasks should tell us when corrected memory is worth keeping.
